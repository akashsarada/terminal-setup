# Humanizer Skill

Apply this skill when drafting, reviewing, or refining human-facing prose, documentation, commit messages, pull request descriptions, or technical explanations.

## Core Principle
Strip machine-generated tropes, formulaic patterns, and buzzword padding while preserving 100% of the technical facts, constraints, and intent.

## Rules for Humanizing Prose

### 1. Eliminate Throat-Clearing & Openers
- Remove formulaic introductory filler: *"In today's fast-paced world"*, *"It is crucial to remember"*, *"Let's dive into"*, *"At its core"*, *"In the realm of"*.
- Start directly with the subject, action, or conclusion.

### 2. Abolish Formulaic Contrast Tropes
- Eliminate synthetic contrasts: *"Not just X, but Y"*, *"While X is powerful, Y is where it really shines"*, *"It's not about X, it's about Y"*.
- State facts directly without rhetorical framing.

### 3. Strip AI Buzzwords & False Enthusiasm
- Remove overused AI filler words: *delve*, *tapestry*, *testament*, *seamless*, *game-changer*, *crucial*, *pivotal*, *furthermore*, *moreover*, *robust* (unless describing algorithmic resilience), *unlock*, *foster*.
- Replace adjective-heavy praise with concrete metrics and evidence.

### 4. Break Formulaic Rhythm
- Avoid mechanical 3-point bullet breakdowns for simple thoughts.
- Vary sentence length naturally: mix short declarative statements with longer explanatory sentences.
- Avoid wrapping every bullet in bold lead-ins followed by a re-statement.

### 5. Preserve Technical Integrity
- NEVER alter technical terms, file paths, function names, metrics, error messages, or code blocks.
- Preserve all constraints, architectural reasons, and acceptance criteria.
